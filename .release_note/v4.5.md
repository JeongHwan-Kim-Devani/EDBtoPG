# Release Note - v4.5 (EPAS 9.4/9.5/11+ Compatibility & Script Maintainability)

Date: 2026-04-21

## Summary
- This release consolidates compatibility fixes across EPAS 9.4, 9.5, and 11+.
- The recommended execution target is now `epas_precheck_v4.5.sh`.
- It also improves script maintainability by removing repeated hardcoded SQL schema filters.

## Included Changes
- EPAS 9.4/9.5 compatibility fixes
  - Replaced `to_jsonb(...)` with `row_to_json(...)` where row-to-JSON access is required.
  - Replaced `jsonb_each_text(...)` with `json_each_text(...)` for resource group field probing.
  - Avoided direct dependency on `pg_proc.proparallel` by using safe JSON-field lookup with fallback (`n/a`).
- EPAS 11+ compatibility fixes
  - Hardened `prokind` branch detection logic to avoid false fallback to legacy columns.
  - Prevented errors such as `column p.proisagg does not exist` in newer catalog layouts.
- Maintainability improvement (v4.5 enhancement)
  - Centralized repeated system schema exclusion list into one variable:
    - `SYSTEM_SCHEMA_LIST`
  - Introduced SQL template token replacement:
    - `__SYSTEM_SCHEMA_LIST__`
  - Added shared truthy evaluator (`is_truthy`) for consistent boolean result handling from `psql` scalar queries.

## Impact
- Fixes representative runtime errors:
  - `ERROR: function to_jsonb(edb_resource_group) does not exist`
  - `ERROR: column p.proparallel does not exist`
  - `ERROR: column p.proisagg does not exist`
- No functional regression intended for existing report outputs (`HTML/TSV`); changes are compatibility and robustness focused.
